Day 16/30 — Tools for Agents

Equipping Agents with Tools

How structured schemas, read-only file/search tools, standardized metadata, and feedback loops give AI agents external capabilities.

1. Three Categories of Agent Tools

An LLM on its own has parametric knowledge but no access to your live codebase or environment. Tools are typed functions exposed to the model via structured schemas:

  • File Tools (e.g. list_files, read_file): Allow the agent to explore file trees and inspect file lines with line-numbering for precise citations.
  • Search Tools (e.g. search_code, grep): Perform fast literal or regex pattern matching across source files, returning repository-relative paths and line excerpts.
  • API Tools (e.g. http_get, query_db): Interact with external REST services, databases, or local runtime environments under strict authorization bounds.

2. Connecting to flue-repo-assistant (PR #7)

In the flue-repo-assistant codebase (tools/), tools are defined using runtime schema validators (Valibot/Zod) and standardized metadata:

  • Tool Selection Rules:
    • list_files: Use when directory structure or file path is unknown.
    • search_code: Use when searching for a symbol, phrase, config key, or implementation whose file path is unknown.
    • read_file: Use when the exact file path is known.
  • Standardized Result Metadata (InspectionMetadata): Every result returns { used, remaining, limit } so the model can monitor budget consumption. Failures are wrapped with wrapWithBudget so remaining budget is visible even after errors.
  • Truncation Accuracy: read_file sets truncated = requestedEnd > endLine || endLine < lines.length to accurately indicate unread lines.
  • Safe Observability: REPO_ASSISTANT_DEBUG=true prints safe single-line summaries logging tool name, sanitized inputs, result counts, and budget snapshots without leaking file content or keys.
