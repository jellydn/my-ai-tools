Day 17/30 — Planning vs Execution

Decoupling Planning from Execution

How task decomposition, plan execution, dynamic replanning, and reflection make multi-step AI agents predictable and reliable.

1. Why Separate Planning from Execution?

When an LLM agent attempts to solve a complex multi-step request without a plan, it risks jumping straight to arbitrary tool calls, repeating searches, or skipping critical steps. Planning enforces structure before execution:

  • Task Decomposition: Breaking a complex user goal into an ordered 3–5 step plan before making any tool inspection calls.
  • Deterministic Step Execution: Executing each planned step sequentially, attaching outputs to the observation history.
  • Dynamic Replanning: Revising the remaining plan when an intermediate search step yields no matches.
  • Plan Reflection: Analyzing executed steps after goal completion to determine if steps could be merged or simplified.

2. Connecting to flue-repo-assistant (PR #9)

In the flue-repo-assistant codebase (planner/ module), planning is implemented via a decoupled architecture:

  • Planning Meta-Tools (create_plan, replan, reflect_plan): Tools that structure reasoning without inspecting the repository or consuming the shared inspection budget.
  • Plan Execution Engine (executor.ts): Runs each step against the read-only inspection tools (list_files, read_file, search_code), tracking step statuses (success, empty, skipped, error).
  • Replanning Triggers (shouldReplan): Detects empty search results and generates a revised plan before continuing execution.
  • Reflection Summaries (reflection.ts): Evaluates total vs executed steps and records whether steps could be simplified.
