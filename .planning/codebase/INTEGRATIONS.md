# External Integrations

**Analysis Date:** 2026-08-04

## APIs & External Services

**OpenAI-compatible AI API:**
- **OpenAI/OpenRouter** — chat completions for `/api/chat`, server-side embeddings for repository retrieval, and document-QA answer generation.
- SDK/Client: `openai` via `lib/openai-client.ts`.
- Auth: `OPENAI_API_KEY`.
- Endpoint/model configuration: `OPENAI_BASE_URL`, `OPENAI_MODEL`, and `OPENAI_EMBEDDING_MODEL`; Dokku normally points the base URL at OpenRouter (`docs/dokku-deploy.md`, `.env.example`).

**Local/hybrid embeddings:**
- **Hugging Face Transformers** — browser index generation with `Xenova/all-MiniLM-L6-v2` in `scripts/index-browser.ts`.
- SDK/Client: `@huggingface/transformers` and `onnxruntime-node`.
- Auth: no application key required by the checked-in browser-index path; model download/network access is required during indexing.

**GitHub:**
- **GitHub REST API** — GitHub App JWTs, installation tokens, repository content, issues/PRs, comments, branches, and pull requests in `src/github-bot/github.ts` and `src/github-bot/worker.ts`.
- SDK/Client: small typed `GitHubClient` wrapper around `fetch`.
- Auth: `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY`, and installation tokens generated at runtime.

**GitHub Skills/Marketplace ecosystem:**
- The repository distributes tool-specific configs, skills, MCP registrations, and plugins for multiple AI coding clients under `configs/` and `skills/`.
- Installation uses external CLIs and package managers through `cli.sh` and `lib/install*.sh`; availability is detected and missing tools are generally skipped or warned about.

## Data Storage

**Databases:**
- No external database or ORM is required by the TypeScript server.
- GitHub bot state is stored as atomic JSON snapshots by `JsonJobStore` in `src/github-bot/store.ts`.

**File Storage:**
- Repository index: `data/index.json` generated by `scripts/index-repo.ts`.
- Browser index: `public/index-browser.json` generated by `scripts/index-browser.ts`.
- GitHub bot durable state: `BOT_DATA_DIR` (production Docker default `/var/lib/my-ai-bot`).
- GitHub bot ephemeral workspaces: `BOT_WORKSPACE_ROOT` (production Docker default `/tmp/my-ai-bot`).
- Document-QA uploads/index artifacts: local filesystem managed by `document_qa/`.

**Caching:**
- No hosted cache. Local tool caches and generated indexes are explicitly excluded or regenerated where appropriate.

## Authentication & Identity

**Auth Provider:**
- **Custom GitHub App authentication** for the bot.
- Implementation: RS256 app JWT creation, installation-token exchange, HMAC-SHA256 webhook verification, collaborator permission checks, and bot-sender filtering in `src/github-bot/github.ts`, `src/github-bot/app.ts`, and `src/github-bot/commands.ts`.

**Application API auth:**
- The public chat and retrieval server has no general user login provider in `server.ts`; it relies on deployment/network configuration and rate limiting rather than account sessions.

## Monitoring & Observability

**Error Tracking:**
- No third-party error tracking integration is configured.

**Logs:**
- Server and indexing paths use standard console output.
- GitHub bot emits structured JSON logs through `jsonLogger` in `src/github-bot/security.ts`.
- GitHub Actions provides CI/deploy logs; health probes are exposed at `/healthz` and `/readyz` in `server.ts`.

## CI/CD & Deployment

**Hosting:**
- **Dokku** — `ai-tools` application deployed by `.github/workflows/dokku.yml` to the configured Docklight host using `dokku/github-action` and SSH.
- **GitHub Pages** — documentation/wiki artifact deployment through `.github/workflows/deploy-pages.yml`.

**CI Pipeline:**
- **GitHub Actions** — `.github/workflows/test.yml` installs BATS and `jq` and runs the CI subset of shell/config tests.
- Dokku workflow validates secrets, synchronizes the OpenRouter key into Dokku config, and pushes `main` to the Dokku Git remote.
- Docker build uses a BuildKit secret for optional build-time repository indexing (`Dockerfile`).

## Environment Configuration

**Required env vars:**
- For chat/indexing: `OPENAI_API_KEY` and compatible model/base URL settings.
- For GitHub bot: `GITHUB_APP_ID`, `GITHUB_APP_PRIVATE_KEY`, `GITHUB_APP_WEBHOOK_SECRET`; optional `GITHUB_BOT_LOGIN` and worker/storage controls.
- For Dokku CI: `DOKKU_SSH_PRIVATE_KEY` plus `OPENROUTER_API_KEY` or legacy `OPENAI_API_KEY` with the expected OpenRouter prefix.

**Secrets location:**
- Local development: untracked `.env` based on `.env.example`.
- CI: GitHub Actions encrypted secrets.
- Runtime/deploy: Dokku app config; the workflow synchronizes the AI key before pushing.
- Build: Docker BuildKit secret mount, not a normal image `ENV` value.

## Webhooks & Callbacks

**Incoming:**
- `POST /api/github/webhooks` in `src/github-bot/app.ts`, accepting GitHub `issue_comment` events and validating `x-github-delivery`, `x-github-event`, and `x-hub-signature-256`.

**Outgoing:**
- GitHub REST API calls for issue/PR comments, labels/status updates, branch pushes, and draft PR creation/reconciliation from `src/github-bot/worker.ts` and `src/github-bot/workspace.ts`.
- No generic third-party webhook callbacks are configured.
